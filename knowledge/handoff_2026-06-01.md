## What was completed today (2026-06-01)

### 1. Root-cause fix: All scheduler services now boot at container start (critical)

**Root cause confirmed:** Streamlit does NOT execute `app.py` at container startup — only when a user first visits the page. This meant APScheduler never initialised if no user visited between container restarts (e.g. 4 AM terraform apply → scheduler never starts → no daily jobs run → reports stop).

**Fix pattern (applied to all 5 market apps):**
- `run.sh` — shell entrypoint that starts a standalone Python scheduler process in the background, then `exec streamlit` as the foreground
- Per-app `scheduler_service.py` (GB) or shared `services/intl_market_common/scheduler_service.py` (AU/ERCOT/PJM/CAISO) — pure Python, no Streamlit dependency, runs APScheduler with all the scheduled jobs
- Terraform task definition `command` updated from hardcoded `["streamlit", "run", ...]` to `["/bin/bash", "apps/{market}-market/run.sh"]` for all 5 apps
- **CRITICAL**: Never revert terraform commands back to direct streamlit invocation — that breaks scheduler boot

**Verified in CloudWatch:** All 5 new containers show:
```
[RUN] {MARKET} scheduler service started (PID N)
[SCHEDULER] {MARKET} standalone scheduler service starting
Uvicorn server started on 0.0.0.0:{PORT}
...
[SCHEDULER] {MARKET} scheduler running. Jobs: [...]
```
The scheduler starts ~8s before Streamlit finishes loading.

## Scheduler boot pattern (apply to all new market apps)
```
apps/{market}-market/
  run.sh               ← starts scheduler in BG, then exec streamlit
  scheduler_service.py ← GB only; others use services/intl_market_common/scheduler_service.py
  Dockerfile           ← CMD = ["/bin/bash", "apps/{market}-market/run.sh"]
```
Terraform task definition `command` must be `["/bin/bash", "apps/{market}-market/run.sh"]`, NOT `["streamlit", ...]`.
